**结论先说：WordPress 可以直接写 Markdown，但要“选对方式”**，因为**核心并不是原生 Markdown 编辑器**。

我按「最推荐 → 次推荐 → 不推荐」给你梳理。

* * *

## ✅ 方案一（最推荐）：用插件直接写 Markdown

### ⭐ 1️⃣ WP Githuber MD（老牌、功能最全）

**适合：重度 Markdown 用户 / 技术博客**

**特点**

-   直接 Markdown 编辑器（不是转换）
-   实时预览
-   支持：
    -   GFM（GitHub 风格）
    -   代码高亮
    -   表格 / TOC / 数学公式
-   可一键切换 Markdown ↔ HTML

**使用方式**

1.  安装插件：  
    后台 → 插件 → 安装插件 → 搜索  
    `WP Githuber MD`
2.  新建文章时：  
    👉 右上角切换到 **Markdown 编辑器**

**体验**

> 类似在写 README.md  
> 比 Gutenberg 舒服得多

* * *

### ⭐ 2️⃣ Jetpack Markdown（轻量稳定）

**适合：不想折腾，只写基础 Markdown**

**特点**

-   官方团队维护
-   支持常用语法：
    -   标题 / 列表 / 链接 / 代码块
-   无复杂 UI

**启用方法**

1.  安装 **Jetpack**
2.  设置 → 写作 → 启用 **Markdown**

⚠️ 不支持太多扩展语法（如 Mermaid、数学公式）

* * *

## ✅ 方案二：用 Gutenberg + Markdown 块（折中）

### 3️⃣ Gutenberg「Markdown」代码块

**适合：偶尔写 Markdown**

**用法**

-   添加区块 → **自定义 HTML / 代码块**
-   粘贴 Markdown
-   由主题或插件解析

⚠️ 缺点：

-   不是真正的 Markdown 编辑器
-   排版、预览不友好
-   长文不推荐

* * *

## 🧠 方案三：外部 Markdown → WordPress（专业写作流）

### ⭐ 4️⃣ 本地 Markdown + 同步

**适合：程序员 / 多平台发布**

**流程示例**

```text-x-trilium-auto
Typora / VS Code
        ↓
Markdown 文件
        ↓
WordPress（插件同步）
```

### 可用插件

-   **WP Markdown Editor**
-   **Markdown to HTML**
-   **Static CMS / Git-based workflow**

这种方式：

-   本地写作体验最好
-   适合长期维护技术站

* * *

## ❌ 不推荐的方式

-   直接在 Gutenberg 里写 Markdown（体验差）
-   复制 Markdown 粘到可视化编辑器（格式会乱）

* * *

如果你问我 **最优解** 👇

### 🥈 普通博客 / 简单 Markdown
